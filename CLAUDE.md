# Lum Browser - rules for Claude

**Language:** talk to the user in Polish. Everything in the repo is in English by default: code, comments,
UI strings, docs, patch descriptions, commit messages and PRs.

The project is made by two people, each working with Claude on their own computer,
synced through GitHub (`lum-browser-team/lum-browser`).

## What the project is

A private, lightweight browser for Windows: a fork of **ungoogled-chromium-windows** with our own layer
of changes in `lum/`. Goals, more important than anything else:
1. **Privacy** - zero telemetry, zero Google/Microsoft services, no network requests without the user's consent.
2. **Lightness** - must run on weak computers (Win 10, 4 GB RAM). Every feature must be cheap in RAM/CPU;
   nothing runs in the background without a need.
3. **A minimalist UI of our own.**

We do not copy code, names, artwork or the look of other browsers (e.g. Helium) - Lum has its own identity.
Patches from ungoogled-chromium/Bromite/Debian etc. are OK if the license allows it and we credit the source.

## Structure

- `lum/patches/` + `lum/patches/series` - **all our changes to the Chromium code**, as `.patch` files.
  Applied last (after ungoogled-chromium and the Windows patches/) by `build.py` (blocks marked `# LUM:`).
- `lum/flags.gn` - our GN flags, appended to the end of `args.gn`. gn runs with `--fail-on-unused-args`.
- `lum/branding/` - logo/icon sources. Binary icons (PNG/ICO) live in `lum/branding/overlay/` in the `build/src` layout
  and `build.py` copies them after the patches (text patches cannot replace binary files). They are generated by
  `lum/branding/generate_icons.py` - run it after every logo change.
- `lum/branding/rebrand_strings.py` - changes "Chromium" to "Lum" in all strings (.grd files + 81 .xtb translations,
  recomputing the translation ids) and sets the authors (Bartłomiej Kulesz, Oleh Nykorovych). Run by `build.py` after
  the patches. An exception to "everything as patches" - such a patch would have tens of thousands of lines.
  Add new string files to `GRD_FILES`; phrases about the Chromium project (not our browser) are protected by `_NAME_RE`.
- `lum/devutils/rebuild.py` - quick rebuild on the existing `build/src` (new patches + icons + strings + ninja).
  It remembers the applied patches in `build/src/.lum-applied`, so **do not change an already applied patch's diff** -
  make the fix a new patch, otherwise a full build is needed (the description at the top may change freely).
- `ungoogled-chromium/` (submodule), `patches/`, `flags.windows.gn`, `downloads.ini`, `pruning.list`,
  `domain_substitution.list`, `package.py`, `.github/`, `devutils/` - **upstream layer. Do not edit**,
  unless it is a base update or the user explicitly asks for it. Upstream changes = conflicts on every update.
- `build/` - Chromium code (`build/src`) and outputs. Ignored by Git. **Changes in `build/src` are lost** on
  a clean build - every Chromium change must be saved as a patch in `lum/patches/`.
- `docs/ungoogled-chromium-windows.md` - the original upstream documentation (dependencies, rust updates etc.).
- **Lum's look**: `docs/lum-ui-spec.md` (spec) + `ui-preview/` (Lum Preview, the working mockup, the reference). Read them before any UI change.
  UI design: olehnykorovych. Authors in `AUTHORS.md` - update it whenever something new has an author.

## Patches

- Paths in patches are relative to the Chromium root (`build/src`), `-p1` format (`a/...` / `b/...`).
- Folders by area: `branding/`, `privacy/`, `perf/`, `ui/`, `features/`.
- Descriptive kebab-case names: `disable-...`, `add-flag-...`, `ui-...`.
- New patch = new file + a line in `lum/patches/series` in the right place. One patch = one thing.
- At the top of a patch a short description (what and why) before the first `---`/`diff`.
- After changing a patch, check that it still applies to a clean source (after the upstream patches).
- Prefer switches (`chrome://flags` / settings) over hard code removal, when that does not hurt privacy.

## Git

- Never commit `build/`.
- **Never push tags** (`git push --tags`) - the workflows in `.github/` start multi-hour builds on every tag.
  The `upstream` remote has `tagOpt --no-tags`.
- Every feature on its own branch (`ui/...`, `privacy/...`, `perf/...`), then a PR to `main`.
- Commits in English, title `area: what changed` (e.g. `ui: vertical tabs`), max ~65 characters.

## Base update (new Chromium)

1. Branch `update/chromium-<version>`.
2. `git fetch upstream` → `git merge upstream/master` (or a specific release commit) → `git submodule update --init`.
3. Chromium version: `ungoogled-chromium/chromium_version.txt`.
4. Build; fix the Lum patches that did not apply for the new code.

## Building

Developer Command Prompt for VS (as administrator): `python3 build.py --tarball`, then `python3 package.py`.
Requirements and fixing failed builds - in README.md.
